# 手机版 · 设置（三步，一次就够）

员工勾选任务 → 工时自动汇总到老板，**全程不需要手动导入**。

---

## 总览

| 步骤 | 做什么 | 耗时 |
|---|---|---|
| **1** | Supabase 里跑四段 SQL | 约 5 分钟 |
| **2** | 装 apk，登录页「创建老板账号」 | 约 1 分钟 |
| **3** | 建员工账号、派任务 | 约 2 分钟 |

**URL 和密钥已经预置在 apk 里了，不用填。**
**老板账号在 App 里自助创建**，员工账号**一键建好**，都不用碰后台。

## 几个老板都能用，各自独立

**每个老板都能在登录页建自己的账号**，互相看不见对方的人、任务和工时。

| | |
|---|---|
| 数据隔离 | 靠数据库的行级权限（RLS），按 `boss_id` 判断 |
| 两个老板看到的东西 | **完全分开**——员工列表、任务、工时都互不可见 |
| 手机号撞车 | 自动加后缀（`19155025818-2`），并**告诉你最终登录名** |
| 员工工号撞车 | 会被拒绝，提示换一个 |

> **验证过**：`node e2e-multiboss.js` 会真建两个老板，检查他们互相看不见对方的数据。

## 第 1 步：跑四段 SQL + 关一个开关

### 1.1 打开 SQL 编辑器

浏览器打开（会直接进到你那个项目）：

```
https://supabase.com/dashboard/project/edchntmyqqjqvpngylgc/sql/new
```

### 1.2 第一段：建表

在电脑上打开 PowerShell，粘这条（**把 SQL 复制到剪贴板**）：

```powershell
Get-Content E:\miniSoftware\ProjectRecorder\mobile\sql\setup-tables.sql -Raw | Set-Clipboard
```

回到浏览器：**点一下黑色编辑框内部** → `Ctrl + V` → 点右下角绿色 **`Run`**。

**预期**：`Success. No rows returned`

### 1.3 第二段：所有功能（建号 / 通知 / 工号解封）

**`Ctrl + A` 全选，`Delete` 清空编辑框**（重要：不要两段混在一起），然后：

```powershell
Get-Content E:\miniSoftware\ProjectRecorder\mobile\sql\migrate-notify.sql -Raw | Set-Clipboard
```

回浏览器 `Ctrl + V` → **`Run`**。预期：`Success. No rows returned`

> **这一段把三件事合在一起了**（原来是三个文件，你只用跑一次）：
>
> | 做什么 | 不跑会怎样 |
> |---|---|
> | **① 一键建员工账号** | 老板建不了员工 |
> | **② 通知功能**（建 `task_events` 表） | 收不到任何通知 |
> | **③ 工号解封** | 员工账号被删过之后，那个工号**永远用不了** |
>
> 「我的」页顶部会显示一条提示，**它就是按这个进度来的**——
> 跑完之后提示自动消失。
>
> **重复跑无害**（都是 `create or replace` / `if not exists`）。

### 1.4 第三段：账号管理（改手机号 / 改密码 / 注销）

**`Ctrl + A` 清空编辑框**，然后：

```powershell
Get-Content E:\miniSoftware\ProjectRecorder\mobile\sql\account-management.sql -Raw | Set-Clipboard
```

回浏览器 `Ctrl + V` → **`Run`**。预期：`Success. No rows returned`

> **这一段让三件"客户端做不到"的事变成可能**：
>
> | 做什么 | 为什么必须服务端做 |
> |---|---|
> | **改登录名**（换手机号 / 换工号） | Supabase 改邮箱要发确认信到新邮箱，我们用的是假邮箱，收不到 |
> | **注销账号** | `anon` key 删不掉 `auth.users` 那一行 |
> | **老板重置员工密码** | 只有账号本人能改自己的密码 |
>
> **「改密码」不需要这段**——改自己的密码客户端就能做。
>
> **重复跑无害。**

### 1.5 第四段：打开"实时推送"（消掉延迟）

**`Ctrl + A` 清空编辑框**，然后：

```powershell
Get-Content E:\miniSoftware\ProjectRecorder\mobile\sql\enable-realtime.sql -Raw | Set-Clipboard
```

回浏览器 `Ctrl + V` → **`Run`**。预期：`Success. No rows returned`

> **这一段决定"多久能收到通知"**：
>
> | 情况 | 派任务后多久弹窗 |
> |---|---|
> | **不跑** | 最慢 **15 秒**（靠轮询） |
> | **跑了** | **1 秒内**（服务器主动推） |
>
> **不跑也能用**，只是慢——所以忘跑的话不会报错，
> 只会觉得"怎么要等一下才出来"。
>
> 顺便说：跑到这段说明你的 Supabase 项目没开表格的实时发布。
> 那是个开关，不开的话订阅会**假装成功**然后什么都不推——
> 所以我做了个脚本能把这种情况查出来。
>
> **重复跑无害。**

### 1.6 关掉邮箱验证

左侧 **Authentication** → **Sign In / Providers** → 点 **Email** → 找到 **Confirm email** → **关掉** → Save

> 不关的话登不上（内部邮箱是假的，收不到确认信）。

## 第 2 步：创建你自己的老板账号

装好 apk 后打开，在登录页**最下面**找到：

```
  还没有账号？创建一个老板账号
```

点它，填三样：

| 字段 | 填什么 | 注意 |
|---|---|---|
| 怎么称呼你 | 王老板 / 张三 | 随便填，只用于显示 |
| 手机号 | 13800138000 | **只能用字母数字和 `. _ -`**，3~20 位，不要中文或空格 |
| 密码 | 至少 6 位 | — |

点「**创建并登录**」，**建好就直接进主界面了**。

> **如果提示"这个号已经被用了"**，说明别人先用了同一个手机号。
> 系统会自动加后缀（比如 `13800138000-2`），并弹提示告诉你
> **最终登录名是哪个**。记下来，下次登录用它。

## 第 3 步：建员工账号 + 派任务

### 3.1 建员工账号

**底部「团队」→ 顶部「员工账号」→ 右上角「+ 账号」**

填姓名、工号、密码 → **创建**（一次就建好）。

建完告诉员工三样：

| 告诉他 | 值 |
|---|---|
| 工号 | 你设的，比如 `A001` |
| 密码 | 你设的 |
| 登录时选 | **「我是员工」** |

**不用去 Supabase 后台，不用再点任何按钮。**

> **工号撞车**：如果提示"已经在服务器上被用了"，
> 说明**别的老板**的团队里有人用了同一个工号。
> 换一个就行（比如 `A001` 改成 `B-A001`）。

### 3.2 派任务

**底部「团队」→ 顶部「派任务」** → 选人、填内容、日期、预估工时 → 派发

员工登录后就能看到，勾掉就自动报工时。

## 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 登录报 `Invalid login credentials` | 密码或身份选错了 | 老板用手机号、员工用工号；**两边不通用** |
| 登录报 `Email not confirmed` | 邮箱验证没关 | 见 1.4 |
| 建员工报 `Could not find the function` | 第二段 SQL 没跑 | 见 1.3 |
| 建员工报 `code may only contain...` | 工号里有中文或太短 | 只能用字母数字和 `. _ -`，3~20 位 |
| 员工说"今天没有任务" | 任务派给了别人，或日期不对 | 派任务时确认选对了人、日期是今天 |
| 老板收不到工时 | 员工那边没上传成功 | 员工端顶栏会显示「同步失败」，点开看原因 |
| 一直显示「待上传 N 条」 | 没网或被服务端拒绝 | 点「立即同步」重试 |
| 忘了密码 | — | 去 Supabase → Authentication → Users 重置 |

| `sql/multi-boss.sql` | 多老板支持的原始迁移（内容已并入上面第二段） |
